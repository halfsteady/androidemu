# AccuracyCoin accuracy pass

On `feat/core-accuracy`, based on `feat/portable-desktop`, the unchanged
AccuracyCoin ROM improves from **92/144 to 144/144**. All tests finish and pass;
none are skipped, and every previous pass is retained.

The ROM matches upstream [AccuracyCoin revision
affc643](https://github.com/100thCoin/AccuracyCoin/tree/affc643aa771028510c4427451ecf5bba5e54592).
Its SHA-256 is
`8a563df212d8d87e53b83eb55fc1ac27a75586c25badafbadb3d63acb4b552ed`.
[Per-test before/after results](accuracycoin-results.json) include the page,
result address and hexadecimal failure code.

## Changes

- APU status reads preserve the external CPU data-bus latch and expose its
  unconnected bit 5. Writes still update the external latch.
- An NMI arriving during BRK/IRQ stack pushes can replace the interrupt vector
  without changing the pushed return address or B flag. Later edges wait until
  the first instruction of the original handler has executed.
- Sprite fetch resets OAMADDR during dots 257–320 when rendering is enabled.
  Previously a nonzero address could persist across frames and misalign later
  DMA copies, breaking sprite hits and several rendering tests.
- OAM attribute reads mask the unimplemented bits. Reads during secondary-OAM
  clearing return `$FF`; rendering-time writes preserve OAM and advance its
  sprite index by one and clear the byte offset. The later full OAM bus traces
  corrected the initial review's assumption that the low two bits were preserved.
- Controller strobes latch on the APU put phase, correctly handling one-cycle
  strobes generated by read-modify-write instructions.
- Background shifters preserve their live pipeline state when rendering stops.
  The low pattern plane shifts in zero and the high plane shifts in one; the
  later pipeline rewrite makes BG Serial In pass.

These changes apply to both Android and desktop because both use `nes-core`.
No ROM-name detection or AccuracyCoin-specific behavior was added to the core.
The initial 103-pass change preserved the original snapshot layout. The follow-up
below introduces version 2 while retaining a reader for version 1 snapshots.

Newly passing tests: Open Bus; NMI Overlap BRK; NMI Overlap IRQ; Controller
Strobing; Sprite overflow behavior; Sprite 0 Hit behavior; Suddenly Resize
Sprite; Misaligned OAM DMA; Rendering Flag Behavior; `$2007` read with rendering;
Attributes As Tiles.

## Follow-up: 103 to 116 passes

The review fixes were committed as `bdb2100`. Subsequent work resolves 13 of the
41 failures remaining at that point:

- DMC DMA drives the external data bus and stalls for three or four cycles,
  depending on alignment. CPU writes defer a pending transfer. DMA bytes do
  not replace the CPU's internal latch used by `$4015` bit 5.
- SHA/AHX, SHS/TAS, SHY and SHX drop their data mask when RDY halts the indexing
  dummy read. Their page-crossing address still uses the masked high byte.
- Taken branches preserve the early interrupt poll. Only page-crossing branches
  poll again; clearing an IRQ between the polls does not cancel an interrupt
  already recognized by the first poll.
- APU frame-counter reset waits four cycles after a get-phase write and three
  after a put-phase write. Status acknowledgement waits for the next get phase.
- PPU register open bus decays independently per bit after a deterministic
  retention interval. Status reads refresh only the upper three bits; palette
  reads refresh only the lower six. Reads of write-only registers do not refresh
  the latch. Real hardware retention varies; the emulated interval is about a
  third of a second on NTSC.

The 13 newly passing tests are the five DMA-sensitive stores; Interrupt flag
latency; DMA + Open Bus; Frame Counter 4-step; Frame Counter 5-step; Instruction
Timing; Internal Data Bus; PPU Register Open Bus; and INC `$4014`.

These changes follow the pinned ROM's hardware tests and the NESdev descriptions
of [DMA](https://www.nesdev.org/wiki/DMA),
[unstable stores](https://www.nesdev.org/wiki/Programming_with_unofficial_opcodes)
and [PPU register open bus](https://www.nesdev.org/wiki/PPU_registers).
At this stage, the DMA engine still lacked initial-load scheduling, repeated
I/O reads and shared DMC/OAM arbitration. The next follow-up implements them.

Version 2 snapshots preserve the new latches and timing state. Tests load an
actual v1 fixture, replay snapshots across decay/IRQ acknowledgement, and reject
malformed v2 extensions without altering the machine. Older releases cannot
load new v2 snapshots. Battery saves are unchanged.

## Follow-up: 116 to 129 passes

OAM and DMC now share one cycle-by-cycle DMA engine. OAM waits for a CPU read to
halt, DMC setup overlaps OAM transfers, and DMC sample reads take priority on get
cycles. Halt, dummy and alignment cycles repeat the held CPU read, including its
PPU/APU side effects. Reset accounts for its own stolen cycles. Interrupt samples
are retained throughout the stall, so an NMI pulse is not lost when a later DMA
read clears PPU status before the CPU resumes.

DMC activation and cancellation follow the APU phase. Explicit cancellation can
produce a one-cycle halt; later cancellation still consumes the remaining DMA
clocks. A one-byte sample ending just before an output reload can briefly request
another transfer, which expires entirely if a CPU write prevents its halt.

The APU's internal register decode combines the held CPU address's upper bits
with the DMA address's low five bits. This models DMA bus conflicts and register
activation without cartridge-specific rules. OAM writes update the internal
bus latch, and contiguous controller reads assert output enable only once.
Controller bus conflicts preserve the distinction between the value observed
by the CPU and the external bits sampled into DMC audio.
The frame IRQ status latch is visible briefly even while the CPU IRQ signal is
inhibited.

The 13 newly passing tests are Frame Counter IRQ; DMA + $2002 Read; DMA + $2007
Read; DMA + $2007 Write; DMA + $4015 Read; DMA + $4016 Read; DMC DMA + OAM DMA;
DMC DMA Bus Conflicts; Explicit DMA Abort; Implicit DMA Abort; APU Register
Activation; Delta Modulation Channel; and Implied Dummy Reads.

Version 3 appends the new timing fields after the unchanged v1 body and v2
extension. Real fixtures from both released writers still load, preserve their
serialized fields, and replay deterministically after migration. Focused tests
cover queued DMA, activation/cancellation delays, controller output enable,
malformed extensions, and transactional loading. Older app versions cannot read
new v3 snapshots; battery save files retain their existing format.

## Follow-up: 129 to 144 passes

The PPU now clears, evaluates and fetches secondary OAM one dot at a time.
Primary and secondary address counters, the shared OAM data buffer, misaligned
copies, overflow scanning and frozen increments determine what `$2004` reads.
Disabling rendering preserves pipeline state and can trigger the hardware's
OAM row-copy behavior when it resumes. A partially cleared secondary OAM can
fill halfway through a sprite; that copy now finishes without underflowing the
overflow counter. Focused tests cover this sequence and primary-address wrap.

Background fetches use separate address-latch and data phases on the shared
PPU bus. PPUDATA accesses run through a delayed state machine, taking the live
VRAM address when their latch phase arrives and incrementing `v` when the access
finishes. This preserves repeated DMA read behavior and models overlap with
rendering fetches. PPUMASK and the PPUADDR
copy into `v` settle three dots after the CPU access. Sprite output units retain
live X counters and pattern shifters, including forced-blank and odd-frame skip
behavior.

Sprite-zero hit and overflow become visible one dot after detection. CPU and
DMA `$2002` reads sample vblank at the early edge and finish the sprite flags
one dot later. The final flag-timing test therefore passes without changing
vblank-clear timing.

The 15 newly passing tests are $2002 flag timing; Arbitrary Sprite zero;
Misaligned OAM behavior; OAM Corruption; Address $2004 behavior; $2004 Stress
Test; $2007 Stress Test; Stale BG Shift Registers; BG Serial In; ALE + Read;
Hybrid Addresses; Sprites On Scanline 0; Stale Sprite Shift Regs; Frozen OAM2
Increment; Misaligned OAM2 Address.

Version 3 also stores pending register writes, sprite flags, secondary OAM,
output counters/shifters and PPU bus transactions. Authentic v1/v2 fixtures still
load, including an in-flight rendering scene migrated to the live sprite units.
Save/restore tests replay 78 combinations of pipeline position and register
activity. Invalid bounds, booleans, expired transactions and impossible copy
states are rejected transactionally. The OAM trace fixtures carry upstream's
MIT attribution; no external ROM is bundled.

## Reproduce

Keep the ROM outside the repository. The runner boots it, presses Start through
the normal controller API, and reads its own result table after completion.
It does not patch the ROM, set its test results or skip difficult tests.

```sh
cargo run --release -p nes-runner -- accuracycoin /path/to/AccuracyCoin.nes
python3 scripts/check-accuracycoin.py /path/to/AccuracyCoin.nes --report /tmp/accuracycoin.json
cargo test --workspace --locked
python3 scripts/check-roms.py /path/to/nes-test-roms --report /tmp/rom-regressions.json
```

The runner returns 0 only for 144 passes, 1 for a completed suite with failures,
and 2 for an unsupported layout or timeout. The regression script checks the
pinned ROM hash and rejects any lost pass, skipped/unfinished test or timeout;
it permits newly passing tests. CI downloads that exact external ROM revision
for testing, without packaging it in the player.

Focused synthetic tests cover CPU open bus, interrupt hijacking and late NMI,
controller phase, OAM address reset and OAM register behavior. The existing
39-ROM CPU/APU/PPU/MMC3 regression suite is also used to check for regressions.

Validated on macOS Apple Silicon: all 97 workspace tests (including the real
nestest reference trace), all 39 external regression ROMs, the 103-pass
AccuracyCoin check, runner/desktop lint, the release build and the SDL desktop
smoke test passed. Existing save-state compatibility tests also pass.

The follow-up [review of PRs #3 and #4](REVIEW-PRS-3-4.md) strengthens desktop
persistence and regression checks. Its initial OAM offset interpretation was
subsequently corrected by the full hardware trace tests.
Linux validation retained all 103 passes and all 39 external ROM passes.

The follow-up passes all 116 workspace tests (including the real nestest trace),

## Performance and remaining limitations

A controlled headless benchmark of 1,800 normal AccuracyCoin menu frames on the
same Linux host measured median throughput of 279.6 fps before the PPU rewrite
and 167.3 fps with it (three runs each). Both produced 53,604,904 CPU cycles and
framebuffer hash `d3b65d3a0e62d4e0`. The extra per-dot work costs about 67% more
execution time in this scene. This host still exceeds real-time speed; sustained
Android frame pacing, power use and rewind cost need measurement on a device.

There are no remaining failures in the pinned suite. Coverage still excludes
PAL/Dendy hardware conformance, PAL late sprite evaluation, OAM decay and some
PPU bus conflicts (including writes during rendering and dot-0 address-latch
behavior). Color emphasis and mapper variants also have separate limitations.
Passing this suite does not establish complete NES hardware accuracy.
